# FR-10 팔 B 뚜껑 덮기: 물건이 든 박스에서 팩킹 구역에 선 직후 물리 엔진(PhysX)이 죽는다

> 작성일: 2026-11-03 · 브랜치: `feature/pw-conveyor-dashboard-polish`
> 범위: 키팅이 끝난 박스(물건 4개)가 팩킹 구역에 서고 팔 B가 뚜껑을 덮기 시작하면 유니티가 멈추거나 죽는다. 사용자 보고: "6번에서 박스가 팩킹 구역에 선 직후 에디터가 멈추거나 죽을 수 있습니다".
> 표시: **확정**(재현으로 확인) · **추정**(정황) · **미검증**(확인하지 않음)
> 시험은 모두 헤드리스(프레임 50fps 고정)다. **에디터에서 직접 확인한 것이 아니다.**

## 0. 한 줄 요약

물건을 쥘 때 물건 충돌체와 씬의 모든 충돌체 사이에 `Physics.IgnoreCollision` 쌍을 수백 개 걸었다. 이 쌍이 많이 걸려 있는 상태에서 팔 B(`LidCoverTask`)가
손가락 관절의 구동 힘 한계(`ArticulationDrive.forceLimit`)를 쓰면, 다음 물리 스텝에서 PhysX 솔버(`PxsSolverStartTask::setupDescTask`)가 죽는다. **확정(재현).**
쌍을 걸지 않고 충돌체의 제외 레이어(`Collider.excludeLayers`)로 같은 효과를 내도록 바꿔 고쳤다.

## 1. 증상 (확정)

- 키팅(팔 A)으로 물건 4개를 박스에 담고, 박스가 컨베이어로 팩킹 구역에 서서 `AtPacking`이 오른 직후, 팔 B가 시작할 때 크래시.
- 크래시 보고서(`%LOCALAPPDATA%\Temp\Unity\Editor\Crashes`)의 위치는 항상 같다: `physx::Dy::PxsSolverStartTask::setupDescTask`, 같은 주소(`0x00007FFE9FC8E7D5`), 종료 코드 `-1073741819`(0xC0000005). 그 앞에 물리 경고 로그는 없다.
- 빈 박스(`ConveyorHandoffTests`)에서는 죽지 않는다. 물건이 든 박스에서만 죽는다.

## 2. 원인을 좁힌 과정 (확정)

죽는 쓰기는 `LidCoverTask.ApplyFingerForceLimit`이다: 팔 B의 회전 손가락 관절에 `d = body.xDrive; d.forceLimit = 5; body.xDrive = d;`. 구동 값 자체는 정상이다.
같은 쓰기는 팔 A의 첫 집기 전에는 안전하다(0.6~6.7초 사이 여러 번 써 봄). 첫 집기 직후(8.7초)부터 죽는다.

키팅 없이 장면을 열고 단계를 하나씩 얹는 재현 시험으로 가렸다(각 단계마다 팔 B 쓰기 + 25프레임). 아래는 모두 같은 구성의 헤드리스 1회씩이다.

| 얹은 것 | 팔 B 쓰기 | 비고 |
|---|---|---|
| 아무것도 안 얹음 | 안전 | |
| 동적 큐브(보간, ContinuousDynamic) 생성 | 안전 | |
| 큐브에 `FixedJoint`로 팔 A 손가락 연결 / 떼기 / 얼리기 | 안전 | 조인트 자체는 원인이 아니다 |
| 충돌 무시 쌍 **0개**(`excludeLayers = 모든 레이어`) | **안전** | 모든 단계 통과 |
| 충돌 무시 쌍 **1개**(팔 B 아닌 충돌체 하나) | **안전** | |
| 충돌 무시 쌍 **36개**(팔 B 충돌체만) | **죽음** | |
| 충돌 무시 쌍 **223개**(관절 몸체 아닌 충돌체만) | **죽음** | 관절 몸체와 쌍을 걸어서가 아니다 |
| 충돌 무시 쌍 **455개**(팔 B 제외 전부) | **죽음** | |
| 충돌 무시 쌍 **491개**(전부) | **죽음** | |

따라서 "쌍의 대상이 무엇이냐"가 아니라 "쌍이 많이 걸려 있느냐"가 변수다. 한계값은 2~35개 사이 어딘가이고 정확히는 모른다(**미검증**).
쌍을 나중에 풀어(2012번의 `IgnoreCollision(false)`) 보아도 회복되지 않았다.

### 가려낸 것(원인이 아님, 각각 시험함)

- 물건 충돌체 끄기, 물건 몸체의 충돌 검출 끄기, 물건 `Rigidbody` 없애기(첫 시도는 `Graspable`이 `Rigidbody`에 의존해 지워지지 않아 **무효**였다. 이전에 "물건 Rigidbody는 원인이 아니다"라고 한 말을 취소했고, `DestroyImmediate`로 조인트 → `Graspable` → `Rigidbody` 순으로 지운 유효한 두 번째 시험에서도 죽어서 결론이 유지된다).
- 팔 A 전체 끄기, 팔 A 부모와 시험용 큐브 끄기.
- 쥐기 직후 같은 프레임의 `SetParent` 간섭(25프레임 늦춰 봄).
- 팔 B 구동 값 손상(값은 정상).
- 박스의 `Rigidbody Interpolate`(이건 별개 문제였고 [FR-05 문서](FR-05_컨베이어를_타는_박스에서_안의_물건이_따로_논다_Rigidbody_Interpolate가_부모_이동을_덮어쓴다.md)에서 고쳤다. 그 수정 전에도 이 크래시는 났다).

왜 쌍 수가 솔버를 죽이는지의 PhysX 내부 이유는 **미검증**이다. 이 문서는 재현으로 확인한 조건과 우회만 다룬다.

## 3. 고친 것

- `ColliderLayerExclusion`(새 파일): 충돌체의 `excludeLayers`를 쓰고 읽는 작은 정적 클래스. 쌍을 만들지 않는다. 어느 레이어를 제외할지는 호출하는 쪽이 넘긴다.
- `PhysicsGraspHolder`: 쥐는 동안 단계별로 제외 레이어를 바꾼다.
  1. 닫는 동안: 물건은 손가락이 놓인 레이어(로봇 팔)와만 부딪히고 나머지(선반, 박스)는 제외. 손가락이 물건에 막혀 멈추는 것은 그대로 남긴다.
  2. 쥔 뒤: 모든 레이어 제외(조인트가 붙잡는다).
  3. 놓을 때(`PlacedItemLanding.PrepareCollisions`): 로봇 팔 레이어만 제외하고 박스, 이미 놓인 물건과는 다시 부딪히게 한다.
  손가락 레이어는 손가락 충돌체에서 읽는다(레이어 이름이나 번호를 코드에 박지 않았다).
- 쓰지 않게 된 `CollisionIsolation`(쌍 방식)과 그 시험을 지웠다.
- 시험: `ColliderLayerExclusionTests` 8개(EditMode). 회귀는 `KitBoxRideTests`의 뚜껑 덮기 포함 시험이 본다(물건 든 박스에서 팔 B가 구동을 쓰는 경로).

## 5. 남은 문제와 한계

- **뚜껑 안착이 간헐적으로 실패한다(4회 중 1회).** 크래시와는 별개다. 물건이 선반에 놓여 있던 때와 다른 기울기로 앉으면(비스듬히 서면) 박스 위로 튀어나와 뚜껑이 그 위에 얹힌다고 **추정**한다(1회차에서 높이가 높은 쪽이었는지 확인하려고 실패 메시지를 가로/높이로 나눠 적게 고쳤으나, 실패한 회차의 로그는 그 전의 것이라 나눠 적힌 값은 없다). 쌍 방식이던 이전 기록에서도 같은 물건의 기울기가 75°/90°, 56°/90°로 갈렸으므로 놓기 편차는 이번 수정 이전부터 있었다.
- **에디터에서 직접 확인하지 않았다.** 헤드리스 결과다.
- 닫는 동안 물건은 팔 레이어의 다른 링크(손바닥 등)와도 부딪힐 수 있다(쌍 방식은 손가락만 남겼다). 물건이 손가락 사이에 있어 닿지 않는다고 보고 정했다. A행(OneKit), B행, C행 E2E 각 1회가 통과했고(멈추지 못한 물건 0개, 크래시 0) 컨베이어 이동 시험(`ConveyorHandoffTests` 2개, 뚜껑 없는 이동)도 통과했다. 랜덤 주문 시험에서는 확인하지 않았다(**미검증**).
- 쌍 수의 한계값(2~35개 사이)은 모른다. 다른 곳에서 충돌 무시 쌍을 많이 걸 일이 생기면 같은 크래시를 의심한다.

## 6. 함정으로 남길 것

- 다른 관절 몸체(`ArticulationBody`)의 구동 값을 쓰는 코드가 있는 씬에서 `Physics.IgnoreCollision` 쌍을 수십 개 이상 걸지 않는다. 물건 하나를 여러 충돌체에서 떼어 놓고 싶으면 `Collider.excludeLayers`(레이어 제외)를 쓴다.
- "죽는 쓰기"와 "죽는 원인"은 다르다. 이 크래시에서 쓰기(`forceLimit`)는 방아쇠였고, 원인은 그 전에 걸어 둔 쌍이었다. 크래시 위치가 같아도 방아쇠를 바꿔 가며 가려야 한다.
- 같은 스택(`setupDescTask`)이 다른 원인으로도 난 적이 있다: 팔 밑동 콜라이더가 베이스 박스에 파묻힌 접촉([TROUBLESHOOTING.md](../TROUBLESHOOTING.md) 1절). 스택이 같다고 같은 원인이 아니다.
- 가르는 시험이 무효였음이 나중에 드러나면(예: `Graspable` 의존으로 `Rigidbody`가 안 지워짐) 이전 결론을 바로 취소하고 다시 한다.
