# 대시보드: 패널을 전부 계층 오브젝트로 바꾸며 만난 문제들 (OnEnable 순서, 배속 예산, 지운 파일에 있던 열거형)

> 작성일: 2026-11-04 · 브랜치: `feature/pw-order-dashboard-hierarchy` · Unity 6000.6.0f1
> 범위: 강사 피드백("OnGUI를 쓰지 말고, 스크립트로 동적 생성하지 말고, 히어라키의 오브젝트로")에 따라 대시보드 패널 9개를 IMGUI/런타임 생성에서 uGUI 프리팹으로 바꾸는 동안 만난 문제
> 표시: **확정**(측정이나 코드로 확인) · **추정**(코드나 정황으로 본 것) · **미검증**(아직 확인하지 않음)

## 0. 한 줄 요약

패널 9개(주문, 배속, 공정 현황, 컨베이어 속도, 선반 재고, 관절 제어, 키팅 로그, 툴 카메라, 인식 표시)를 프리팹으로 만들어 씬의 `DashboardCanvas` 아래에 놓았고, `Dashboard`·`Demo` 코드에서 `OnGUI`/`GUILayout`/`GUIStyle`/`new GameObject(`는 없어졌다(`grep`으로 확인). **헤드리스(배치)에서 EditMode 시험과 패널 씬 시험은 통과했지만, 에디터에서 사람이 직접 눌러 본 확인은 아직 없다 (미검증).** 아래는 그 과정에서 만난 함정 셋이다.

## 1. 부모의 OnEnable이 자식의 Awake보다 먼저 돈다 (확정)

- 증상: 선반 재고 패널에서 부모(`ShelfRowItem`)가 `OnEnable`에서 칸 목록(`Tiles`)을 구독했는데 목록이 비어 있어 구독이 걸리지 않았다.
- 원인: 씬이 켜질 때 같은 오브젝트 계층에서는 부모의 `Awake`와 `OnEnable`이 자식의 `Awake`보다 먼저 돈다. 칸 목록을 자식 `Awake`가 채우는 구조라서 부모 `OnEnable` 시점에는 비어 있었다.
- 고침: 자식 목록을 부모(화면) 쪽에서 `GetComponentsInChildren`으로 늦게 얻는다(첫 사용 때). 자식이 스스로 등록하게 두지 않는다.
- 같은 규칙: 화면(`View`)이 자식 컴포넌트의 `Awake`로 채워지는 값을 `OnEnable`에서 쓰지 않는다.

## 2. 2배속이 소요 시간을 절반으로 줄이지 못했다 (확정, 집기 Fault는 고침)

- 증상(FR-15): 2배속으로 돌려도 키팅 소요 시간이 절반이 되지 않았다.
- 원인: 한 프레임에 이어서 계산해도 되는 시간 예산(`FrameBudget`)이 배속과 상관없이 고정이었다. 배속이 오르면 프레임 하나가 시뮬레이션 시간으로 그만큼 길어지는데, 계산에 쓰는 프레임 수는 그대로여서 계산이 걸리는 시뮬레이션 시간이 배속 배로 늘었다.
- 고침: 예산에 지금 배속을 곱한다(`FrameBudget`의 `speed` 인자). 배속을 모르거나 0 이하(멈춤)이면 1배속으로 본다. 2배속 소요가 약 54%로 줄었다.
- 7키트를 2배속(50fps 고정)으로 돌리면 7번째 키트 B-1에서 가끔 집기 Fault("그리퍼를 닫았지만 물건을 쥐지 못했다")가 나서 `Abort → 박스 제거 → 2초 뒤 새 박스`가 되던 문제(영상에서 박스가 멋대로 생기던 현상)는 원인을 찾아 고쳤다. 물건은 쥐었는데 빈손 판정 기준(0.85)이 얇은 채혈관의 닫힘(0.834~0.857)과 겹친 것이었다. 기준을 0.95로 올려 2배속 7키트 7/7을 3번 통과했다(헤드리스). 경위는 [`FR-15_2배속_7키트에서_가끔_집기_Fault_…`](FR-15_2배속_7키트에서_가끔_집기_Fault_빈손_판정_기준_0.85가_얇은_채혈관_닫힘과_겹쳤다.md). 1배속·EditMode·패널 시험 재실행과 에디터 확인은 아직이다.
- 4배속은 사용자 결정으로 뺐다: 코드(`SimClock.AllowedSpeeds` = 0.5/1/2)와 배속 패널 프리팹(`Speed_4` 버튼)까지 반영했고 `SimClockTests`·`SimSpeedPanelSceneTests`가 통과했다(헤드리스). 경위는 FR-15 문서 5장.

## 3. IMGUI 파일을 지웠더니 그 안에 있던 열거형 때문에 컴파일이 깨졌다 (확정)

- 증상: 쓰지 않는 IMGUI 파일 31개를 지운 뒤 `error CS0246: 'SegmentTone'을 찾을 수 없다`가 나서 모든 시험이 시작도 못 했다.
- 원인: `SegmentTone`(진행 막대 칸의 상태) 열거형이 `SegmentBar.cs`(IMGUI 위젯) 안에 같이 선언돼 있었다. 위젯만 지우려다 열거형도 같이 사라졌고, 그것을 쓰는 `SegmentLook`·`KittingSegmentTones`가 깨졌다.
- 고침: 열거형을 `SegmentTone.cs`로 따로 되살렸다.
- 앞으로: 파일을 지우기 전에 그 안의 `enum`/`struct`/`interface` 선언을 먼저 훑는다(`git show HEAD:파일 | grep -E "enum|struct|interface"`). 이름이 파일 이름과 같다고 해서 파일 안에 그것만 있는 것은 아니다.

## 4. 그 밖에 알게 된 것 (확정)

- 플레이 시작 때 코드가 패널을 만들던 `RecognitionMarkerBootstrap`(`[RuntimeInitializeOnLoadMethod]`로 `new GameObject`)이 있었다. 키팅 로그, 툴 카메라, 인식 표시가 이것으로 생겼기 때문에 "씬에는 없는데 플레이하면 보이는" 패널이었다. 지금은 모두 씬에 놓인 프리팹이다.
- 씬에 클래스만 사라진 `ArmDemoPanel` 컴포넌트가 로봇암 `ur3_with_gripper`에 남아 있었다. `LegacyPanelCleanup`이 로봇암 오브젝트도 살피게 해서 `Setup Dashboard Panels`를 돌리면 뗀다.
- 로그 줄의 글처럼 줄바꿈이 되는 글은 레이아웃이 다음 그리기 전에야 높이를 정하므로, 맨 아래로 내리는 일(`verticalNormalizedPosition = 0`)은 줄을 바꾼 다음 프레임에 한다.
- 배치 모드에서는 `WaitForEndOfFrame`이 돌아오지 않고 마우스 클릭도 못 하므로 시험은 `onClick.Invoke()`·`slider.value =`로 접점을 직접 부른다. PlayMode 씬 시험은 Unity 프로세스 하나에 클래스 하나만 돌린다(묶으면 도구 카메라의 RenderTexture 오류로 둘째가 실패한다).

## 5. 아직 남은 것

- 에디터에서 패널 9개를 직접 눌러 보는 확인(사용자).
- `DemoPanelLayout`은 이제 제품 코드에서 쓰는 곳이 없고 시험(`DemoPanelLayoutTests`, `DemoPanelRectAnchorTests`, `DemoPanelSlotsTests`)만 쓴다. uGUI 자리가 옛 IMGUI 자리와 같은지 비교하는 기준으로 남겨 두었다.
- 집기 판정 기준을 바꾼 뒤의 1배속 7키트 재실행(위 2번). EditMode와 패널 시험은 다시 돌려 통과했다.
- 공정 완료 뒤 주문을 다시 적용하면 공정 현황이 멈추던 문제는 고쳤다. 경위는 [`대시보드_공정_완료_뒤_주문을_다시_적용하면_…`](대시보드_공정_완료_뒤_주문을_다시_적용하면_공정_현황이_멈춘다_주문을_불러올_때마다_키트_순번이_1부터_다시_시작한다.md).
