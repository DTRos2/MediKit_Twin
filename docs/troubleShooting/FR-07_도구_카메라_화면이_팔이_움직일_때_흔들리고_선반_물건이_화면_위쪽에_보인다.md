# FR-07 도구 카메라: 팔이 움직일 때 화면이 흔들려 오류처럼 보이고, 선반에서 물건이 화면 위쪽에 보인다

> 작성일: 2026-11-04 · 브랜치: `feature/dhj-tool-camera-stabilize`
> 범위: 로봇암 A의 도구 카메라(`ToolCameraFeed`)가 키팅 중 보여 주는 `툴 카메라` 패널 화면. 인식 표식이 어긋나는 문제는 [표식 문서](FR-07_도구_카메라_화면의_타겟_표식이_로봇이_움직인_뒤_물건에서_어긋난다.md)에 따로 적었다.
> 표시: **확정**(작성자가 에디터 Play로 확인) · **추정**(코드로 본 것) · **미검증**(아직 확인하지 않음)
> 흔들림 원인은 측정하지 않았다. 코드를 읽고 추정했고, 고친 뒤 증상이 사라진 것만 확인했다.

## 0. 한 줄 요약

카메라가 손(도구 링크)의 자식으로 단단히 붙어 있어, 팔 물리가 만드는 작은 끊김과 떨림이 화면 전체의 흔들림으로 그대로 보였다. 카메라를 손에서 떼어 손의 목표 자세를 지수 필터로 따라가게 해서 흔들림이 없어졌다. 따로, 그리퍼 가운데 카메라가 똑바로 앞만 봐서 선반 물건이 화면 위쪽에 걸렸고, 카메라를 위로 들어 올리는 각도 설정을 추가했다.

## 1. 증상

1. **키팅하는 내내 화면이 흔들린다 (확정).** 물건을 잡고, 옮기고, 박스에 넣을 때까지 `툴 카메라` 패널 화면이 흔들려 사용자가 보기에 오류가 난 것처럼 보였다.
2. **씬과 게임 화면에서는 팔이 흔들려 보이지 않는다 (확정).** 같은 때 Scene 뷰와 Game 뷰에서는 로봇팔의 흔들림이 보이지 않았다.
3. **선반에서 집으러 갈 때 물건이 화면 위쪽에 보인다 (확정).** 스크린샷에서 인식 결과가 `칸 A-2, 거리 0.14m, 화면 (0.54, 0.77)`이었다. 조준 원(가운데)이 아니라 위쪽에 물건이 있었다.

## 2. 원인

### 2-1. 손에 붙은 카메라가 손의 작은 움직임을 그대로 보여 줬다 (추정)

- 카메라(`ToolCamera`)는 도구 링크 `ArticulationBody`의 자식이고, 매 프레임 `LateUpdate`에서 그린다. 팔은 `FixedUpdate`(물리 스텝)에서만 움직이고 `ArticulationBody`에는 보간이 없다. 그래서 렌더 프레임과 물리 스텝이 어긋나면 같은 자세를 여러 프레임 그리다가 갑자기 한 번에 움직인다.
- 손끝의 작은 회전 떨림은 밖에서 보면 안 보이지만, 손에 붙은 카메라에서는 시야 전체가 흔들리는 것으로 확대된다. 2번 증상(씬과 게임 화면에서는 안 보임)과 맞는다.
- 두 가지 중 무엇이 얼마나 컸는지는 가르지 못했다(미검증). 팔 자체가 실제로 크게 떠는 것은 아닌 것으로 본다(확정: 작성자가 씬과 게임 화면에서 확인).

### 2-2. 카메라가 도구 끝점과 같은 쪽을 똑바로 봤다 (확정: 코드와 스크린샷)

- 그리퍼 가운데에 단 카메라(`HandCenter`)는 회전이 항상 단위 회전이었다(`ToolCameraPlacement.AtHandCenter`). 선반에서 집으러 가는 자세에서는 물건이 시선 축보다 위에 있었다.
- 스크린샷 값으로 계산하면, 거리 0.14m에서 세로 시야각 70°의 반높이는 약 0.098m이고 화면 y 0.77은 가운데에서 0.27 × 2 × 0.098 ≈ 5cm 위다. 각도로는 atan(0.053 / 0.14) ≈ 20°다.

## 3. 고친 것

- **카메라를 손에서 분리하고 자세를 따라가게 했다 (`ToolCameraFeed`).** 도구 링크에는 목표 자세만 가진 빈 오브젝트 `ToolCameraTarget`을 달고, `ToolCamera`는 씬 루트로 떼어 그 자세를 지수 필터로 따라간다. 위치는 Lerp, 회전은 Slerp이고 계수는 `1 - exp(-dt / 시간)`이라 프레임레이트가 달라도 지연이 같다.
- **설정 `Smoothing Seconds` (`ToolCameraSettings`).** 기본 0.08초, 범위 0~0.5. 0이면 예전처럼 손에 붙은 그대로 움직인다. 클수록 부드럽지만 화면이 손보다 늦게 따라온다.
- **`CameraPose`도 걸러진 자세를 돌려준다.** 화면과 인식 표식이 같은 자세를 기준으로 하게 하기 위해서다. 인식(`SimulatedItemPoseEstimator`)도 이 자세를 읽는다.
- **설정 `Camera Pitch Up` (`ToolCameraSettings`).** 그리퍼 가운데 카메라를 위로 들어 올리는 각도(도). 기본 20, 범위 -45~45. 유니티는 X축 양의 회전이 아래를 보므로 `Quaternion.Euler(-각도, 0, 0)`으로 돌린다. 옆면 장착과 Manual은 영향이 없다.
- 로봇이 사라져 목표 오브젝트가 없어지면 카메라도 스스로 정리한다.

## 4. 확인

| 항목 | 결과 |
|---|---|
| 필터를 넣은 뒤 `툴 카메라` 패널 흔들림이 없어졌는가 | **확정**(작성자: "흔들림 없어졌어") |
| 카메라를 20° 들어 올린 뒤 선반 물건이 화면 가운데에 오는가 | **미검증**(작성자 확인을 받지 못했다) |
| `ToolCameraPlacementTests`의 위로 20° 시험(새로 추가) | **미검증**(실행 결과를 받지 못했다) |
| 화면이 손보다 0.08초 늦게 따라오는 것이 인식에 영향을 주는가 | **미검증**. 도착 직후 인식이 `OutOfView`로 실패하는 일이 있는지 보지 못했다 |

## 5. 아직 확인하지 못한 것

- 20°는 거리 0.14~0.15m(접근 거리 `_shelfApproachDistance` 0.15m) 한 장면에서 계산한 값이다. 칸마다 높이가 다르면 약간씩 어긋날 수 있다(추정). 위쪽에 보이면 올리고 아래쪽으로 내려가면 줄인다.
- 화면 위쪽이 도구 끝점의 +Y라고 가정했다. 반대로 움직이면 부호를 다시 본다.
- 흔들림이 물리 스텝 어긋남 때문인지 손끝 떨림 때문인지는 가르지 못했다. 팔이 실제로 떠는지는 도구 링크 자세를 `FixedUpdate`마다 기록해 목표와 비교해야 알 수 있다.

## 6. 재발 방지·확인 방법

- **화면만 흔들리고 Scene·Game 뷰의 팔은 멀쩡하면 카메라 쪽을 먼저 본다.** 카메라를 손에 단단히 붙이면 손끝의 작은 움직임이 화면에서 크게 보인다. `Smoothing Seconds`를 0.12~0.15로 올리거나, 너무 늦으면 0.05로 낮춘다.
- 카메라의 자세를 읽는 코드를 새로 쓸 때는 `ToolCamera`가 손의 자식이 아니라는 점을 기억한다. 손의 실제 자세가 필요하면 `ToolCameraTarget`이나 도구 링크를 읽는다.
- 선반 물건이 화면 가운데에서 벗어나 보이면 `Camera Pitch Up`을 조정한다. 위쪽에 보이면 값을 올린다.
