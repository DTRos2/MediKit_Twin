# FR-15: 2배속 7키트에서 가끔 집기 Fault가 나고 박스가 멋대로 생긴다 (빈손 판정 기준 0.85가 얇은 채혈관의 닫힘과 겹쳤다)

> 작성일: 2026-11-04 · 브랜치: `feature/pw-order-dashboard-hierarchy` · Unity 6000.6.0f1
> 범위: 7키트를 2배속으로 돌릴 때 7번째 키트 B-1에서 가끔 나던 집기 Fault와, 영상에서 본 "박스가 멋대로 생기는" 현상
> 표시: **확정**(측정이나 코드로 확인) · **추정**(코드나 정황으로 본 것) · **미검증**(아직 확인하지 않음)

## 0. 한 줄 요약

물건은 제대로 쥐었는데 "손가락이 끝까지 닫혔으면 빈손"이라는 판정 기준(닫힌 비율 0.85)이 가장 얇은 물건(채혈관)을 쥘 때의 닫힘(0.834~0.857)과 겹쳐서, 0.85를 넘는 때 빈손으로 오판했다 (확정). 기준을 0.95로 올려 **2배속 7키트 7/7을 3번 연속 통과**했다 (헤드리스). 고친 뒤 1배속·EditMode·패널 시험 재실행과 에디터 확인은 아직이다 (미검증).

## 1. 증상 (확정)

- 7키트 `DefaultOrder`를 2배속(프레임 50fps 고정)으로 돌리면 가끔 7번째 키트 B-1에서 Fault가 났다.
  - `선반 칸 A-1에서 집지 못했다. 그리퍼를 닫았지만 물건을 쥐지 못했다: 손가락이 물건에 닿지 않고 끝까지 닫혔다 — 물건 중심이 도구 끝점에서 0.005m`(쥐는 반경 0.060m)
- Fault가 나면 `KittingProcess.Abort` → `KitBoxSupply.RemoveBox`로 박스를 올려 지우고 2초 뒤 새 박스가 내려온다. 이것이 영상에서 본 "박스가 자기 마음대로 생긴다"의 정체다 (확정, 코드 경로로 확인).
- 같은 시험을 4배속으로 돌리면 통과했고, 2배속에서도 매번 나지는 않았다(간헐).

## 2. 원인을 좁힌 과정

1. 문구가 "손가락이 물건에 닿지 않고 끝까지 닫혔다"인데 **물건 중심은 도구 끝점에서 5mm**였다. 물건이 손 한가운데 있는데 "닿지 않았다"고 하니, 못 쥔 것이 아니라 **판정이 틀렸을 가능성**을 먼저 봤다.
2. `PhysicalGraspVerdict.FailureReason(isHolding, canSenseContact, isBlocked)`에서 "쥠(`IsHolding`)은 참인데 막히지 않음(`isBlocked` 거짓)"이 이 문구다. `isBlocked`는 `GripClosureJudge`가 손가락 중 가장 덜 닫힌 것의 닫힘 비율이 기준(`_fullyClosedRatio`, 0.85)보다 **작을 때** 참이다. 즉 비율이 0.85 이상이면 "끝까지 닫혔으니 사이에 물건이 없다"고 본다.
3. 판정이 얼마나 아슬아슬했는지 보려고 닫힘 비율을 로그로 남겼다(`LeastClosedRatio`, "쥐기 마침 — … 손가락 닫힘 0.xxx" 줄). 채혈관(1.0×4.6×1.0cm)을 쥘 때 **0.834 ~ 0.857**이 나왔다. 기준 0.85가 그 범위 한가운데에 있었다 (확정).
4. 빈 손으로 닫으면 얼마나 닫히나 재려고 시험 `GripperEmptyClosureTests`를 만들었다. `Scene_Cell`의 모든 `JointGripper`를 열었다 닫아 보니 **0.9982 / 0.9991**이었다 (확정).
5. 그래서 기준은 채혈관(최대 0.86)보다 높고 빈 손(0.998)보다 낮은 곳이면 된다 → 0.95.

## 3. 고침 (확정)

- `JointGripper`의 기준을 0.85 → **0.95**로 올렸다. 툴팁에 "빈 손 0.998 이상, 가장 얇은 물건 0.83~0.86, 그 사이인 0.95"라고 근거를 적었다.
- **필드 이름을 `_fullyClosedRatio` → `_emptyClosedRatio`로 바꿨다.** 직렬화 필드는 기본값만 바꾸면 씬에 저장된 옛 값(0.85)이 덮어써서 안 먹힌다. 이름을 바꾸면 저장된 값이 버려지고 새 기본값이 들어간다.
- `GripClosureJudge`에 `LeastClosedRatio`를 나눠 뽑고(`IsBlocked`는 이것을 기준과 비교), `IGripContact`에 `LeastClosedRatio`/`FullyClosedRatio`를 더했다(구현은 `JointGripper`뿐).
- 진단으로 남긴 것: `GraspClosingTrace`(닫히는 동안 손가락-물건 거리를 물리 단계마다 기록, 실패했을 때만 로그), 쥐기 끝의 닫힘 비율 로그.

## 4. 확인

| 시험 | 결과 |

## 5. 4배속을 뺀 이유와 상태

- 사용자 결정: "4배속까지는 필요없어" → "4배속은 빼줘". 허용 배속을 0.5 / 1 / 2로 한다.
- 문서(`CONVENTION.md`, `docs/INTERFACES.md:183`)에 이어 **코드도 고쳤다** (확정, 헤드리스):
  - `SimClock.AllowedSpeeds`를 `{ 0.5f, 1f, 2f }`로 바꿨다. 새 시험 `SimClockTests`가 허용 배속과, 4·3·0·-1배를 거절하고 배속이 그대로인지 본다(5개 통과).
  - 배속 패널 프리팹은 **그 패널만** 다시 만들었다(`DashboardPanelsSetup.RebuildSimSpeedAndSave`, 메뉴 `Tools/MediKit/Rebuild Sim Speed Panel Prefab`). `Rebuild Dashboard Panel Prefabs`는 패널 9개를 모두 처음 모양으로 되돌려 손으로 고친 부분이 사라지므로 쓰지 않았다. `PF_SimSpeedPanel`에서 `Speed_4` 버튼만 빠졌고 다른 패널 프리팹은 바뀌지 않았다.
  - `SimSpeedPanelSceneTests` 통과(버튼 수가 허용 배속 수와 같은지 본다).
- 남은 것: SRS의 FR-15 허용 배속 문구를 0.5/1/2로 고치는 일은 팀 합의가 필요해서 SRS는 건드리지 않았다. `SimSpeedPanelTextsTests`의 `Speed(4f)`("4배")와 `SimSpeedButtonKindsTests`의 `For(4f, 2f)`는 글자 만들기·버튼 종류 계산이 임의의 수를 다루는지 보는 시험이라 그대로 두었다.
- SRS FR-15의 허용 배속 문구도 같이 고쳐야 한다(팀 합의).

## 6. 남은 것 / 모르는 것

- 왜 2배속에서 더 자주 났는지는 **미검증**이다. 프레임 타이밍에 따라 손가락 닫힘이 0.85 경계의 위아래로 갈린 것으로 **추정**한다.
- 더 얇은 물건이 생기면 닫힘이 0.95에 가까워질 수 있다. `GripperEmptyClosureTests`가 기준과 빈 손 값 사이의 여유(0.03)를 지키는지 본다.
- 앞으로: "쥠은 참인데 빈손 판정"이 나오면 물건 위치(도구 끝점과의 거리)부터 본다. 가까운데 "닿지 않았다"면 잡기 실패가 아니라 판정 기준 문제다.
