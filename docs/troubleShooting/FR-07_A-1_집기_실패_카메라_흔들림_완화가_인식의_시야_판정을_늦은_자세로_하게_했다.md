# FR-07 / FR-03: 도구 카메라 흔들림 완화를 넣은 뒤 A-1 집기가 실패한다 (인식이 시야를 늦게 따라오는 카메라 자세로 판정했다)

> 작성일: 2026-11-04 · 브랜치: `feature/pw-dashboard-ugui-panels` · Unity 6000.6.0f1
> 범위: 키팅 중 로봇암 A가 선반 칸 A-1에서 물건을 집지 못하고 `Fault`로 멈추는 문제. 원인은 도구 카메라(`ToolCameraFeed`)의 흔들림 완화와 인식(`SimulatedItemPoseEstimator`)의 시야 판정이 같은 "늦게 따라오는 자세"를 쓴 것
> 표시: **확정**(실험이나 측정으로 확인) · **추정**(코드나 정황으로 본 것) · **미검증**(아직 확인하지 않음)
> **상태:** 헤드리스에서 고쳐 통과했다. **에디터에서 직접 확인한 것은 아니다.** 커밋 전에 도구 카메라를 만든 팀원에게 `SensorPose` 도입을 알려야 한다.

## 0. 한 줄 요약

develop 병합(#45)으로 들어온 `78faad9`(11-04 12:00)가 도구 카메라를 손에서 떼어 손의 목표 자세를 0.08초 늦게 따라가게 했다. 그런데 인식이 "물건이 시야에 들어오는가"를 이 **늦은 자세**로 판정해서, 팔이 막 선반 앞에 도착한 순간 A-1 물건이 시야 밖으로 잘못 판정됐다. 인식이 실패하면 "계획한 자리 그대로 집는다"로 넘어가는데, 계획한 자리는 실제 물건에서 26cm 떨어져 있어 손가락이 허공에서 닫혔다. 인식은 걸러지지 않은 손의 실제 자세(`SensorPose`)로 판정하게 바꿔 고쳤다.

## 1. 증상 (확정)

헤드리스 키팅 시험(`KittingEndToEndTests.OneKit_...`)이 시뮬레이션 8.3초에 이렇게 끝났다.

```
fr5_robot: 칸 A-1: 카메라로 물건을 확인하지 못했다 — 시야 밖 — 칸 A-1 물건이 카메라 화면이나 거리 범위를 벗어났다. 계획한 자리 그대로 집는다.
KittingStation: 키팅이 Fault로 끝났다. 선반 칸 A-1에서 집지 못했다. 그리퍼를 닫았지만 물건을 쥐지 못했다: 손가락이 물건에 닿지 않고 끝까지 닫혔다(물건이 손가락 사이에 있지 않다) — …
[E2E] 결과: 오류로 중단 — 키트 0/1개 (시뮬레이션 8.3초, 실제 5.1초, 배속 1배)
```

- 같은 칸에서 멈추는 [에디터 전용 A-1 집기 정지](FR-03_에디터_플레이에서만_A-1_집기가_멈춤_프레임_간격이_길면_관절_오차가_허용을_넘는다.md)와는 다르다. 그쪽은 "팔이 시간 안에 알려 준 관절 각도에 닿지 못했다"이고, 이쪽은 "카메라로 물건을 확인하지 못했다 — 시야 밖"이 먼저 찍힌다.
- 같은 시험이 이전 코드(`b4cbcc9`까지)에서는 통과했다. 프레임을 50fps로 고정한 헤드리스에서 확인한 실패다.

## 2. 원인을 좁힌 과정

### 2-1. 사용자 커밋이 아니다 (확정)

마지막 사용자(pw) 커밋 `b4cbcc9`까지는 시험이 통과했다. 실패가 시작된 것은 develop 병합 #45로, 이 병합이 가져온 코드 변경은 도구 카메라 파일 3개뿐이다. 그중 `78faad9`(작성자 dev-learning1)가 흔들림 완화(`_smoothingSeconds = 0.08`)와 위로 들기(`_pitchUpDeg = 20`)를 넣었다.

### 2-2. 두 값 중 원인은 흔들림 완화다 (확정: 값을 바꿔 시험)

| 실험 | 결과 |
|---|---|
| `_pitchUpDeg` 0만 바꿈 (`_smoothingSeconds` 0.08 그대로) | **실패** (A-1, 8.3초 중단) — 위로 들기를 끄는 것만으로는 안 고쳐진다 |
| `_smoothingSeconds` 0만 바꿈 | 통과 (키트 1/1, 시뮬레이션 74.5초) |
| `_pitchUpDeg` 20 + `_smoothingSeconds` 0 | 통과 (키트 1/1, 74.4초) |

위로 들기는 상관이 없고, 흔들림 완화가 원인이다. (Unity가 이 두 값을 `Scene_Cell.unity`에 `_pitchUpDeg: 20`, `_smoothingSeconds: 0.08`로 자동으로 채워 넣었다. 스크립트 기본값과 같아 동작은 다르지 않다.)

### 2-3. 왜 시야 밖이 되나 (확정: 코드, 추정: 정확한 거리)

- `ToolCameraFeed.CameraPose`는 흔들림 완화 때문에 손(`ToolCameraTarget`)을 지수 필터로 **늦게** 따라간다.
- `SimulatedItemPoseEstimator`가 `CameraPose`로 물건을 화면에 투영해 시야 안인지, 다른 물체에 가려지는지 판정한다.
- 팔이 선반 앞에 막 도착했을 때는 카메라가 아직 손의 도착 자세에 못 왔다. 선반 칸 A-1의 물건은 시야 가장자리에 있어서, 늦은 자세에서는 시야 밖(`OutOfView`)으로 판정됐다 (카메라가 얼마나 뒤처졌는지는 재지 않았다, 미검증).
- 인식이 실패하면 `계획한 자리 그대로 집는다`로 넘어간다. 이 칸의 **계획한 자리는 실제 물건에서 26cm 떨어져 있었다**. 보정(인식이 알려 주는 물건 자리)을 못 받으니 허공에서 닫혀 `손가락이 물건에 닿지 않고 끝까지 닫혔다`가 됐다.

## 3. 고친 것

화면에 그리는 자세와 인식이 판정하는 자세를 분리했다. 화면은 흔들림 완화로 늦게 따라가도 되지만, 인식은 손의 실제 자세로 봐야 한다.

| 파일 | 변경 |
|---|---|
| `Scripts/Common/IToolCameraView.cs` | `Pose SensorPose` 추가. 설명에 "물건이 시야에 들어오는지·가려지는지 가리는 인식은 화면이 아니라 이 자세로 한다"를 적음. `CameraPose` 설명도 "화면에 보이는 자세, 손이 빨리 움직인 직후에는 실제 자세와 다르다"로 고침 |
| `Scripts/ArmA/ToolCameraFeed.cs` | `SensorPose => _target != null ? 목표(손에 붙은 걸러지지 않은 자세) : CameraPose`. `CameraPose`는 그대로(표식 그리기용) |
| `Scripts/ArmA/SimulatedItemPoseEstimator.cs` | 시야·가림 판정에 `_camera.SensorPose` 사용 |
| `Tests/EditMode/ArmA/PerceptionFakes.cs` | `FakeCameraView.SensorAt`(가짜 카메라의 실제 자세) |
| `Tests/EditMode/ArmA/SimulatedItemPoseEstimatorTests.cs` | 3개 추가: `WhatTheCameraSees_FollowsTheHandPose_NotTheLaggingDisplayPose`, `AnItemOutsideTheHandsView_IsOutOfView_EvenIfTheDisplayPoseWouldSeeIt`, `TheLineOfSightStartsAtTheHand_NotAtTheLaggingDisplayPose` |

- 화면용 `CameraPose`(늦게 따라감)는 표식 그리기에 그대로 쓴다. 표식은 화면과 같은 자세여야 어긋나지 않는다 ([표식 문서](FR-07_도구_카메라_화면의_타겟_표식이_로봇이_움직인_뒤_물건에서_어긋난다.md)).
- 흔들림 완화 값(0.08초)과 위로 들기(20°)는 그대로 두었다. 팀원의 해결(화면 흔들림·물건이 위쪽에 보임)을 되돌리지 않는다.

## 5. 아직 확인하지 못한 것

- 에디터에서 직접 눌러 보지 않았다.
- 카메라가 손에서 정확히 얼마나 뒤처져 시야 밖이 되는지는 재지 않았다. 선반 칸마다 다를 수 있다 (추정). 지금은 모든 칸이 실제 자세로 판정하므로 영향이 없다.
- 이 수정은 팀원의 도구 카메라 파일(`ToolCameraFeed`, `IToolCameraView`)을 건드린다. 커밋 전에 팀원에게 알려야 한다.

## 6. 재발 방지·확인 방법

- **화면을 위해 걸러 낸 자세는 판정에 쓰지 않는다.** 도구 카메라 자세를 읽는 코드를 새로 쓸 때, 화면에 그리는 것이면 `CameraPose`, 시야·가림·거리처럼 사실을 판정하는 것이면 `SensorPose`를 쓴다.
- 흔들림 완화(`_smoothingSeconds`)나 카메라 필터를 바꿀 때는 A행 한 키트 시험(`OneKit_IsPickedFromTheShelf_CarriedAndPlacedInTheBox`)을 돌린다. 인식 실패 로그(`카메라로 물건을 확인하지 못했다 — 시야 밖`)가 한 줄이라도 나오는지 본다.
- 인식이 실패해 "계획한 자리 그대로 집는다"로 넘어가는 경로는 계획한 자리가 틀리면 허공에서 닫힌다. 로그에 이 줄이 보이면 집기 Fault보다 앞의 인식 단계를 먼저 의심한다.
